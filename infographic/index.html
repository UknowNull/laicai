02

四大能力支柱

P0 = MVP 必做
PILLAR · A

实时自动记账

Android 通知捕获：来源预过滤 → 正文提取 → 确定性解析 → 去重合并 → 自动入账或待确认。

PILLAR · B

确定性账本

金额/方向/余额由确定性代码控制；原生 SQLite 存储；多账户自动匹配；手动记账兜底。

PILLAR · C

跨端账单导入

微信/支付宝 CSV、通用 CSV/OFX/QIF、PDF/OCR、分享扩展 —— iOS 的关键替代入口。

PILLAR · D

云端 LLM 分析

确定性指标 + 可追溯周期报告 + 自然语言问答；显式授权、最小化上传、一键可关。

03

一次自动记账的处理链路

确定性优先 · 全程无 LLM 参与
STEP 1
来源预过滤
按包名/标题识别微信、支付宝、银行通知，非目标直接丢弃
→
STEP 2
正文提取
extras / MessagingStyle / tickerText，限制最大长度
→
STEP 3
确定性解析
金额、收支方向、商户、时间 —— 规则代码提取，不靠模型
→
STEP 4
去重合并
SHA-256 外部 ID + 银行×钱包时间窗合并
→
STEP 5
置信度判定
高置信 → 直接入账；否则 → 待确认
→
STEP 6
入账 / 待确认
确认前不影响收支与预算统计
LLM 边界：不决定金额、借贷方向、余额与去重结果 —— 只负责分类建议、趋势解释、异常提示与自然语言问答，且结论可下钻到原始交易。
04

隐私与安全设计

隐私即竞争力
通知正文不落盘
仅内存解析，只保存结构化交易字段；App 无后台联网权限
AES-256-GCM 备份
PBKDF2 高迭代派生密钥，加密备份可恢复，导入前校验
云端分析可关
显式授权 + 最小化上传 + 一键关闭，关闭后仅保留本地确定性指标
05

四阶段实施路线

对齐调研报告 §9 建议优先级
PHASE 1 · 可信记账核心

Android 自动记账 + 双端账本

通知捕获、去重、置信度、待确认闭环；手动记账；账户识别；原生 SQLite；通用 CSV 模板。

PHASE 2 · 跨端导入能力

全格式账单导入

微信/支付宝官方账单、CSV/OFX/QIF、PDF/OCR、分享扩展与导入映射器。

PHASE 3 · 周期分析

确定性指标 + 云端 LLM 报告

月度指标与异常检测由规则计算；显式授权的云端 LLM 生成可追溯分析报告。

PHASE 4 · 连接与同步

银行连接与跨设备同步

视目标市场接入银行/Open Banking 聚合，评估端到端加密同步。
