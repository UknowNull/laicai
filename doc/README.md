# 来财记账 文档系统

## 1. 文档目的

本目录是「来财记账」的持续工程上下文。文档分为稳定基线、领域知识、需求记录、问题记录、架构决策、代码快照和历史参考。它们共同服务于人工开发、代码审查和模型接手。

项目根目录的 [AGENTS.md](../AGENTS.md) 是开发和智能体的规则入口；本文档是项目知识入口。

## 2. 渐进式阅读原则

智能体只需先读取根目录 `AGENTS.md`，由其中的任务路由表选择最小文档集合。不要默认读取 `00-08`、所有领域文档或整个 `requests/`、`issues/` 目录。

- 单领域任务通常只需要一份 `domains/*.md`、相关代码和测试。
- 跨模块需求才需要补充架构、不变量和 ADR。
- 需求/问题记录先用 `rg` 按标题或领域检索，再打开命中文件。
- `generated/` 只在需要核对工程骨架、数据契约时读取。
- `references/` 只在用户明确要求追溯历史、竞品或原型时读取。

本文供人工浏览和文档治理使用，不是每次开发的强制阅读项。

## 3. 目录职责

| 路径 | 职责 | 权威性 |
| --- | --- | --- |
| `00-08` | 项目、需求、架构、约束、流程、验证、模型接手、运维和验收基线 | 高 |
| `domains/` | 按代码/模块边界维护行为、契约、入口、测试和已知限制 | 高 |
| `domains/build-release.md` | 打包/发布/版本号（version.json、build-release.sh、release.yml） | 高 |
| `requests/` | 每个需求从提出到关闭的生命周期和追溯信息 | 需求级 |
| `development/` | 按需求维护的数据契约、模块边界、实施阶段、测试、迁移、回滚和迭代复盘（`RETRO-*`） | 开发设计级 |
| `issues/` | 独立 Bug、回归、测试缺口和已知问题 | 问题级 |
| `decisions/` | 重要架构取舍及其原因 | 决策级 |
| `generated/` | 从当前代码整理或未来由脚本生成的参考快照 | 代码快照 |
| `references/` | 历史原型、竞品调研、设计规范和 UI 原型索引 | 参考，不覆盖代码 |

项目根目录的 `PRD.md`、`DESIGN_SPEC.md`、`UI_SWAP_PLAN.md` 是需求与设计阶段的完整全文，保留用于追溯；`doc/00-02` 与 `doc/domains/` 是后续维护的规范入口。

## 4. 文档更新规则

- 新需求先在 `requests/` 建立需求记录，批准后再更新产品基线。
- 跨模块需求同时在 `development/` 建立 `DEV-YYYYMMDD-name.md`；开发设计必须标注当前状态，不能把计划写成已实现。
- 修改模块行为时更新对应 `domains/` 文档。
- 修改不变量、接口、数据模型或架构时同步更新约束、生成快照或 ADR。
- 发现独立问题时使用 `issues/`，修复后补回归测试并记录验证结果。
- `generated/` 文件应注明生成来源和日期；将来由脚本生成后不得手工编辑。
- 完成开发前运行 `python3 scripts/doc_audit.py`。它只检查本次 Git 变更和命中的 REQ/BUG，不扫描全部领域文档，也不替代人工维护需求与代码之间的语义映射。

## 5. 状态词汇

- 需求：`proposed`、`approved`、`implementing`、`verified`、`closed`、`blocked`。
- 问题：`open`、`investigating`、`fixed`、`verified`、`wont-fix`。
- 能力：`已实现`、`部分实现`、`预留`、`待验证`、`不在范围`。
- ADR：`accepted`、`superseded`、`deprecated`。
