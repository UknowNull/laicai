# 来财记账 工程不变量

这些规则是跨模块契约。修改代码时必须判断是否影响它们；若确实需要改变，必须更新本文、相关测试和 ADR。

## 核心不变式

| 编号 | 不变量 | 主要验证 |
| --- | --- | --- |
| INV-MONEY-01 | 金额以最小货币单位整数存储（分）；展示层再格式化 | `react-app/src/engine/ledger.js` 格式化函数、生产存储设计 |
| INV-MONEY-02 | 金额、借贷方向、去重、余额由确定性代码控制；LLM 不得决定交易数值 | 解析器单测、LLM 上下文组装测试 |
| INV-TIME-01 | 时间统一 UTC 毫秒存储；展示层本地化 | 数据模型测试 |
| INV-DEDUP-01 | 外部去重 ID = SHA-256(`${source}|${merchant}|${amount}|${timeWindow}`)；跨渠道时间窗合并不得破坏单渠道 ID | 去重单元测试 |
| INV-CONF-01 | 低置信或分类不明确的记录必须进入待确认；确认前不影响收支与预算统计 | 状态机测试 |
| INV-PRIVACY-01 | 通知正文仅在内存解析、不落盘；App 无后台外联权限（Android） | 安全审计、权限声明 |
| INV-PRIVACY-02 | 云端 LLM 分析必须显式授权、最小化上传、可一键关闭；关闭后功能不降级 | 授权开关测试、网络抓包 |
| INV-HONEST-01 | 对外表述保持诚实边界：自动归集可获取的交易 + 便捷导入确认；不承诺读取所有支付行为；iOS 不做实时通知读取 | 文案与产品文档审计 |
| INV-THEME-01 | 主题系统遵循「一套引擎 + 三套 Token + 三套布局」；新增主题不得复制引擎逻辑 | 代码结构审查 |
| INV-SYNC-01 | 三版原型（`prototypes/`）与 `react-app/` 数据模型一致；变更必须三处同步 | 数据比对测试、文档审计 |
| INV-EXT-01 | 外部 LLM 调用必须有超时、阶段名、错误处理与用量记录 | LLM 适配层测试 |
| INV-BUILD-01 | React 工程必须可 `npm run build`；产物以 HTTP 访问（file:// 会 CORS 拦截 ES 模块） | 构建 + 冒烟测试 |
| INV-DOC-01 | 每次需求/Bug/重构完成必须同步维护 `doc/` 体系（见 `AGENTS.md` 第 6 节） | `scripts/doc_audit.py` |
