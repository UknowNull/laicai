# 来财记账 项目上下文

## 1. 一句话定位

来财记账 = Android 实时自动记账为尖刀、跨端账单导入为底座、云端 LLM 周期分析为增值的「确定优先」记账应用。

## 2. 核心流水线

```text
支付通知（微信/支付宝/银行 App）
  -> Android 通知捕获（包名/标题预过滤）
  -> 正文提取（extras/MessagingStyle，限长）
  -> 确定性解析（金额/方向/商户/时间，规则代码）
  -> SHA-256 去重 + 跨渠道时间窗合并
  -> 置信度判定
      ├─ 高置信 + 分类明确 -> 直接入账
      └─ 低置信/不明确 -> 待确认（确认前不影响收支统计）
  -> 本地账本（原生 SQLite）-> 确定性月度指标
  -> 云端 LLM 周期报告/问答（显式授权，可下钻，可关闭）
```

## 3. 运行形态

- **Android 端（规划）**：Capacitor/RN 壳 + 原生通知监听插件；通知正文仅内存处理不落盘；本地 SQLite。
- **iOS 端（规划，后补）**：账本 + 账单导入 + 分享扩展；不做实时通知读取（系统限制）。
- **前端工程（当前）**：`react-app/` 为 Vite + React 18 主题化骨架（一套引擎 + 三套 Design Token + 三套布局组件）。
- **原型（当前）**：`prototypes/` 三版独立 HTML 高保真原型（简约/时尚/奢华），带 iPhone 设备框与交互动画。
- **AI**：云端 LLM（显式授权、最小化上传、可关闭）；解析与统计由确定性代码执行。
- **数据**：金额最小货币单位整数；时间 UTC 毫秒；去重 ID SHA-256。

| 平台发布 | 无 | 不在范围 |

## 5. 当前判断基线

1. 实际代码和测试是当前实现事实（`react-app/`、`prototypes/`）。
2. `doc/01-product-requirements.md` 是产品验收基线。
3. `doc/domains/` 是模块行为和数据契约基线。
4. `doc/references/` 中的历史计划、竞品和原型仅解释设计来源。
5. 设计文档中「规划」「预留」等表述不能覆盖代码已实现状态。
6. 三版原型与 `react-app/` 内容必须保持一致；数据模型变更三处同步（原型、引擎、文档）。
